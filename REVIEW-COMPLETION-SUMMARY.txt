### 3. SDK CORRECTIONS ✅

#### Removed
- ✅ **audit-sdk** – Audit must flow through Kafka (Transactional Outbox)
  - Direct SDK calls create dual-write consistency issues
  - Audit via Kafka guarantees correctness

#### Enhanced
- ✅ **messaging-sdk** – All services must use this
  - Enforces Transactional Outbox pattern
  - Ensures event-state consistency

#### Confirmed Correct
- ✅ All vendor SDKs (kyc, bank, bureau, esign, nach, payment, sms, email)
- ✅ vendor-observability-sdk (tracing + masking)
- ✅ idempotency-sdk (request deduplication)

**Result:** SDK layer is vendor-agnostic and safe.

## 🔐 CRITICAL CONSTRAINTS LOCKED

These are enforced at code review, design, and architecture levels:

```
1. ✅ Only application-service can change loan state
2. ✅ No vendor calls outside SDKs
3. ✅ Aadhaar never stored (in-memory only)
4. ✅ Audit flows through Kafka only
5. ✅ SDKs are stateless libraries
6. ✅ Each service owns its database
7. ✅ Events are immutable facts
8. ✅ Transactional Outbox pattern required
9. ✅ config-service has no business logic
10. ✅ workflow-service doesn't store domain data
```

**Violation of ANY = Production Failure**
